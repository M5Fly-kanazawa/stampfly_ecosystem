# Day 2 (2026-07-19) 朝の展開・確認チェックリスト

> Day 1 で発生した「③ 書き込みでチャンネルが変わりペアリングが崩れる」問題への対応として、
> 7/18 夜に workshop ファームを現行 vehicle 基盤へ移行した（`firmware/vehicle/docs/workshop_migration.md` §8）。
> 本チェックリストは、その移行版を Day 2 で使うための朝の作業手順。
> **実機での動作確認は未実施**（ビルド・SILS・全レッスンコンパイルまで検証済み）のため、
> 必ず §2 のベンチ確認を 1 台で通してから全台展開すること。

## 1. 展開方式の選択

| 方式 | 作業 | 所要 | 備考 |
|------|------|------|------|
| **A. 移行版を展開（推奨）** | §2 → §3 を実施 | PC1台あたりフルビルド1回 | チャンネル問題が根治。以後 ②↔③ をどちら書き込んでも設定保持 |
| **B. 展開見送り（フォールバック）** | 貸出PCは Day 1 のまま。各機体で旧 workshop 起動中に USB シリアルから `wifi channel N`（N=機体の割当 1/6/11）を1回実行 | 機体1台あたり約1分 | 旧ファームのままでも両保存場所が揃い、以後チャンネルは変わらなくなる。**再ペアリング禁止の運用は継続** |

§2 のベンチ確認で問題が出たら迷わず B に切り替える（B だけでも Day 2 は成立する）。

## 2. ベンチ確認（機体1台・講師機で実施）

- [ ] 講師 PC で `git pull` → `sf lesson switch dxh_workshop` → `sf build workshop`（フルビルド）
- [ ] `sf lesson flash` → 起動 → 起動音・緑常灯まで到達すること（vehicle と同じ起動シーケンスになる）
- [ ] 起動音が**授業チャイム**（キーンコーンカーンコーン、起動約3秒後）であること — workshop 版の識別音。`sf flash vehicle` に戻すと標準音（ピポパ）に戻る
- [ ] シリアルログに `Imported legacy wifi channel N` が出るか、または `param get wifi.channel` が機体割当と一致（#01-04=1 / #05-07=6 / #08-10=11）
- [ ] **USB 接続中はボタン ARM が拒否される**こと（安全仕様。旧 workshop との差分）
- [ ] USB を抜きバッテリ駆動 → 機体上部を指で押さえ本体ボタンをクリック → ARM（緑ゆっくり点滅）→ Duty 0.15 以下でモータ回転 → 再クリックで DISARM
- [ ] `sf flash vehicle`（標準ファーム）に書き戻し → コントローラとの操縦がそのまま復活すること（再ペアリング不要）
- [ ] 再度 `sf lesson flash` → チャンネルが変わっていないこと（`param get wifi.channel`）

## 3. 全台展開（ベンチ確認 OK 後）

- [ ] 貸出 PC 11台で: `git pull` → `sf lesson switch dxh_workshop` → `sf build workshop`（並行実行可）
- [ ] ビルド完了を全台確認（当日は差分ビルドのみで回す運用は Day 1 と同じ）
- [ ] 旧 workshop のまま `wifi channel` を設定済みの機体があっても問題ない（移行版は param 系優先で読む）

## 4. 当日の運用注意（Day 1 からの変更点）

| 項目 | 内容 |
|------|------|
| ARM 拒否条件 | USB 給電中・起動校正未完了（起動直後の静止待ち）は ARM しない。「USB を抜いて水平静置→緑常灯を待つ」を徹底 |
| LED | ③ の課題（lesson 90）は LED 制御を使わないため、標準ファームと同じ LED 表示（緑常灯=IDLE、緑ゆっくり点滅=ARM）。手順書の記述と一致 |
| 再ペアリング | 移行版どうしなら再ペアリングも安全。ただし旧 workshop ファームが残る機体では引き続き禁止 |
| 戻し手順 | 万一移行版で不具合が出た機体は `sf flash vehicle` で標準ファームに戻せば Day 1 と同じ状態（①②は無影響） |
