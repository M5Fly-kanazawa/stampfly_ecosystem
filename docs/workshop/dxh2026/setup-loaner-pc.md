# DXH講座 貸出PC・機材セットアップ手順書

> **DXH講座運営用の内部文書。** 高校教員には配布しない。講師・運営スタッフ専用。

## 0. この文書について

2026-07-18(土)・07-19(日) 開催の DXH（高等学校DX加速化推進事業）高校教員向け体験講座で使用する、大学貸出の Windows 11 PC 10台＋機材10セットの事前セットアップ手順とリハーサル計画をまとめる。準備締切は **7/17**。

対象読者はセットアップ作業を行う講師・運営スタッフ。手順は上から順に1台ずつ実施し、チェックボックスに沿って進める。

参照文書:

| 文書 | 内容 |
|------|------|
| `docs/setup/windows.md` | Windows 開発環境構築手順（本手順書のベース） |
| `docs/workshop/workshop_guide.md` §機材チェックリスト | 通常勉強会の機材確認項目 |
| `docs/workshop/workshop_schedule.md` §7 準備物 | 通常勉強会の準備物一覧 |
| `docs/workshop/dxh2026/equipment-checklist.md` | 本講座の機材数量・当日チェックリスト |

**表記ルール:** 未実測・未確認の項目には【リハーサル確認】【リハーサル実測】と明記している。断定できない数値・挙動をこの文書内で創作しないこと。リハーサルで判明した実測値は、本文書だけでなく `docs/workshop/dxh2026/handout.md` や `docs/workshop/dxh2026/curriculum.md`（別途作成予定）の該当箇所にも反映すること。

## 1. PC 1台あたりのセットアップ手順

貸出 PC 10台 + 予備1台の**合計11台**に対して、以下の手順を1台ずつ実施する。所要時間は【リハーサル実測】欄に記録する（§3参照）。

### 1-1. アカウント・権限の確認

- [ ] Windows へ管理者権限（または `winget` 実行に必要な権限）でログインできることを確認 【リハーサル確認】
- [ ] 大学の貸出PCがドメイン参加・グループポリシーで `winget` やインストーラの実行が制限されていないか確認 【リハーサル確認】
- [ ] 制限がある場合は情報システム部門に事前相談し、講座当日までに解除・代替手順を確定する

### 1-2. 前提ツールの導入（winget）

CMD を開き、以下を確認・導入する。

```cmd
git --version
python --version
```

- [ ] `git --version` が表示されない場合: `winget install Git.Git`
- [ ] `python --version` が Python 3.8 未満・未導入の場合: `winget install Python.Python.3.12`
- [ ] 導入後は CMD を開き直してから再確認する

### 1-3. リポジトリの取得

```cmd
git clone https://github.com/M5Fly-kanazawa/stampfly_ecosystem
cd stampfly_ecosystem
```

- [ ] `C:\stampfly_ecosystem` （またはチームで統一した場所）に clone できることを確認

### 1-4. install.bat の実行（ESP-IDF + sf CLI 自動導入）

```cmd
install.bat
```

- [ ] `install.bat` が ESP-IDF のダウンロード・インストールと sf CLI のセットアップを完了することを確認
- [ ] 所要時間を記録（§3のリハーサル記録シートへ）
- [ ] エラー時は `docs/setup/windows.md` §7 トラブルシューティング（Python 未検出時の PATH 設定等）に従う

### 1-5. VSCode のインストール

- [ ] VSCode 未導入の場合: `winget install Microsoft.VisualStudioCode`
- [ ] `sf lesson edit` がエディタとして VSCode を自動起動できることを後の手順（1-8）で確認する

### 1-6. 開発環境のアクティベートと動作確認

```cmd
cd stampfly_ecosystem
setup_env.bat
sf doctor
```

- [ ] `sf doctor` の全項目が OK になることを確認（NG があれば個別に解消してから先に進む）

### 1-7. 機体の USB 接続確認

- [ ] StampFly を USB-C ケーブル（データ通信対応）で PC に接続する
- [ ] デバイスマネージャーの「ポート (COM & LPT)」に「USB JTAG/serial debug unit (COMx)」が表示されることを確認（ESP32-S3 内蔵USBのためドライバ不要のはず）【リハーサル確認】
- [ ] 認識されない場合はケーブルを充電専用でないものに交換し、別の USB ポートで再試行する

### 1-8. デスクトップフラッシャ類の配置

- [ ] `C:\StampFly\` フォルダを作成する
- [ ] `StampFlyFlasher_v2026.07.1_windows-x64.exe` を `C:\StampFly\` に配置する
- [ ] `stampfly_vehicle_v2026.07.1_full.bin` を `C:\StampFly\` に配置する（教室でGitHub Releaseの匿名APIレート制限（60回/時/IP）に当たらないよう、当日は「ローカルファイル」モードで使うため）
- [ ] `.exe` を1回起動し、SmartScreen の警告（未署名のため表示される）で「詳細情報」→「実行」を選び、正常に GUI が起動することを確認しておく（2回目以降は警告が出ない想定）【リハーサル確認】

### 1-9. Workshop ファームの事前ビルド

当日は「編集→差分ビルド→書き込み」のみで進めるため、事前に1回フルビルドを済ませておく。

```cmd
sf lesson switch 1
copy docs\workshop\dxh2026\user_code_dxh.cpp firmware\workshop\main\user_code.cpp
sf lesson build
```

- [ ] `sf lesson switch 1` は Lesson 1（モータ制御）に切り替える。**ビルドディレクトリを全削除しフルビルドになるため、当日この場では絶対に再実行しない**（当日は差分ビルドのみで時間内に収める）
- [ ] DXH実習コードを導入: `copy docs\workshop\dxh2026\user_code_dxh.cpp firmware\workshop\main\user_code.cpp` （`sf lesson switch 1` はLesson 1の雛形で `user_code.cpp` を上書きするため、必ず switch の後に実行する。当日 switch を再実行するとこのテンプレートが消える点に注意）
- [ ] `user_code.cpp` の内容がDXH版（冒頭コメントに「DXH workshop exercise template」）であることを確認
- [ ] `sf lesson build` が成功することを確認し、所要時間を記録（§3）

### 1-10. 書き込みリハーサル（workshop ファーム）

```cmd
sf lesson flash
```

- [ ] 書き込みが成功し、書き込み後にシリアルモニタが自動起動することを確認（終了は `Ctrl+]`）
- [ ] 所要時間を記録（§3）
- [ ] `sf lesson flash` は NVS（設定保存領域）を消さないため、この時点ではペアリング情報は保持されたままであることを確認

### 1-11. リリースFWへの書き戻し（Webフラッシャ）

Lesson 1 ファームを書き込んだままにしないよう、講座当日の状態（操縦体験で使うリリース vehicle ファーム）に戻す。

- [ ] ブラウザ（Edge/Chrome）で https://m5fly-kanazawa.github.io/stampfly_ecosystem/flash/ を開く
- [ ] 「StampFly 本体」カードの「⚡ インストール」→ ポート選択 →「接続」→ INSTALL 実行（Erase device チェックは OFF）
- [ ] 完了後、機体が自動再起動し起動音が終わるまで水平静置することを確認
- [ ] **この書き戻しにより機体は未ペア状態に戻る**（full イメージはNVSも上書きするため）。ペアリングは §2 の手順でセットごとに行う

### 1-12. 完了チェック

- [ ] 上記 1-1 〜 1-11 全てにチェックが付いていることを確認
- [ ] PC本体・付属品（電源アダプタ等）に貸出セット番号ラベルを貼る（§2と対応）

## 2. 機材セットの準備（機体・コントローラ・PC・ケーブルの対応付け）

10セット（+予備）それぞれについて、機体・コントローラ・PC・ケーブルを1つのグループとして管理する。

### 2-1. セット番号ラベル

- [ ] 機体・コントローラ・PC・USB-Cケーブルの4点に、同一のセット番号ラベル（例: `#01`〜`#10`、予備は `#S1`）を貼付する
- [ ] ラベルは机上での取り違え防止のため、受講者が座る机にも同じ番号を掲示する

### 2-2. ペアリング（1セットずつ）

**★複数の未ペア機を同時に電源ONするとクロスペアリング（別セットのコントローラと誤って対になること）が起こるため、必ず1セットずつ実施する。**

各セットについて:

- [ ] 対象セット以外の機体・コントローラの電源は OFF にしておく
- [ ] コントローラの M5 ボタン（画面下）を押しながら電源ON → ペアリングモード（青点滅+ド→ソ音）に入る
- [ ] 機体の電源を ON にする（1-11 でリリースFWに書き戻し済み・未ペア状態）
- [ ] 機体を発見しペア成立（青点滅停止+ビープ）することを確認
- [ ] コントローラLCDのMAC表示と機体のセット番号ラベルを照合し、意図した組み合わせになっていることを確認
- [ ] 完了したセットの機体・コントローラの電源をOFFにしてから次のセットに進む

### 2-3. コントローラの Device ID 割当

- [ ] コントローラのタッチメニューで Device ID を設定する。ID=0（親機）は1台のみに割り当て、他は 1〜9 の一意な値にする
- [ ] 10台同時運用時の干渉有無は【リハーサル実測】（§3）

### 2-4. スティックモードの統一

- [ ] 全コントローラのスティックモードが **Mode 3**（右スティック=スロットル/ヨー、左スティック=ピッチ/ロール）に統一されていることを確認する（講座は Mode 3 で教える。2026-07-16 決定）
- [ ] 確認方法: フライト画面の文字色が**黄 = Mode 3**（緑 = Mode 2）。違っていたらコントローラのメニューから Stick Mode を切り替える（設定は本体に保存され、電源を切っても保持される）

### 2-5. バッテリー

- [ ] 各セットのバッテリーが満充電（4.2V）であることを確認する
- [ ] 予備バッテリーも満充電にしておく（必要本数は `equipment-checklist.md` 参照）

|---------|--------|-------|-------|------|
| 機体起動〜緑常灯（準備完了）までの時間 | 約10秒 | | | マゼンタ点滅（ジャイロ校正中）の長さも記録 |
| Webフラッシャでの書き込み時間（接続〜完了） | ― | | | ポート選択〜INSTALL完了まで |

- [ ] 10台同時飛行に干渉が確認された場合は、同時飛行数を絞る運用（数人ずつ順番に飛ばす）や Device ID 割当を見直す

## 4. 講座終了後の復元手順

各日の講座終了後、翌日 or 返却に向けて機材を工場出荷相当の状態に戻す。

### 4-1. リリースFWへの書き戻し

- [ ] 各機体に `stampfly_vehicle_v2026.07.1_full.bin` を書き戻す。**GUIフラッシャのローカルファイルモードが確実**（Webフラッシャでも可）
- [ ] 各コントローラに対応するリリースFWがあれば同様に書き戻す（`stampfly_controller_v2026.07.1_full.bin`）

### 4-2. 再ペアリング（1セットずつ）

- [ ] §2-2 と同じ手順で、1セットずつ再ペアリングする（クロスペアリング防止のため同時電源ON禁止）

### 4-3. 動作確認

- [ ] 各セットで ALT_HOLD による1フライト（自動離陸→ホバリング→自動着陸）を実施し、正常動作を確認する

### 4-4. バッテリー充電

- [ ] 全セットのバッテリーを充電する（充電中は目を離さない）

### 4-5. 数量確認・返却準備

- [ ] `equipment-checklist.md` の機材一覧と照合し、数量に過不足がないか確認する
- [ ] 破損・不具合があった機材を記録し、返却前に大学側へ報告する
- [ ] セット番号ラベルを剥がす（返却物品に指示がある場合）
