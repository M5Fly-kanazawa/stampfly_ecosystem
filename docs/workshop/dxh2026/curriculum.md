**安全上の注意（講義で必ず伝える）:**

- Duty の上限はファームウェアでは強制されない（小数点のタイポで `1.0` と書くと全開で回る）。**隣同士で数値をダブルチェックしてからビルドする運用**を徹底する
- プロペラは装着したままで実施する。回転させる際は必ず機体上部の M5StampS3 基板を上から指で押さえた状態にしてから ARM する
- 動作確認は USB を外したバッテリー駆動で行う（USB接続中はARM自体が拒否される仕様のため、書き込み確認とモータ回転確認は工程が分かれる）

**実習コード（`docs/guides/motor_spin_quickstart.md` §6-3 準拠・正本）:**

`sf lesson edit` で開くと以下のコードが入っている（貸出PCに導入済み）。各モータごとに1行ずつ並んでおり、回したいモータの数値（Duty）を 0.0〜0.15 の間で設定すればそのモータが回り、0.0 のままならそのモータは止まったままである。

```cpp
#include "workshop_api.hpp"

// =========================================================================
// Motor duty test (hardcoded)
// 各モータの Duty をハードコードする
// =========================================================================
//
// Motor IDs / モータ ID:
//   1 = FR (右前)   2 = RR (右後)
//   3 = RL (左後)   4 = FL (左前)
//
// Duty range: 0.0 - 1.0
//   0.0  = stop / 止める
//   0.10 = spin at 10% / 10% で回す
//   このチュートリアルでは 0.15 を上限とする

void setup()
{
    ws::print("Motor duty test");

    // Do NOT auto-arm in code. Arming is controlled by the controller's
    // ARM button or a single click of the vehicle's onboard button, so
    // motors never spin until you intentionally press it.
    // コードでは自動 ARM しない。アーム/解除はコントローラの ARM ボタン
    // または機体本体ボタンの単クリックで行うので、意図的に押すまで
    // モータは絶対に回らない
}

void loop_400Hz(float dt)
{
    // ----- Set each motor's duty here / 各モータの Duty をここで設定 -----
    ws::motor_set_duty(1, 0.10f);   // FR (右前)
    ws::motor_set_duty(2, 0.00f);   // RR (右後)
    ws::motor_set_duty(3, 0.00f);   // RL (左後)
    ws::motor_set_duty(4, 0.00f);   // FL (左前)
    // -------------------------------------------------------------------
}
```

> 本講座の③④ではコントローラを使わず、機体本体ボタンの単クリックでARM/DISARMする（コード中コメントの通り、どちらの方法でもARMできる）。

## 6. リスクと対応表

| リスク | 予兆・症状 | 対応 | 備考 |
|-------|-----------|------|------|
| 機体故障（モータ不動作・プロペラ破損） | 起動LEDシーケンスが進まない／異音／プロペラ破損 | 予備機に即交換。当該セットは講座終了後に原因調査 | 予備機2台を確保（`equipment-checklist.md`） |
| ビルドが遅い・固まる | ③④実習でビルドが実習時間内に終わらない | 隣席とペア作業に切替える | 事前フルビルド済みのため通常は差分ビルドで短時間の想定【リハーサル実測】 |
| Webフラッシャ書き込み失敗 | ポート未検出／進捗が進まない | GUIフラッシャの「ローカルファイル」モードに切替（オフラインでも動作） | `C:\StampFly\` に `StampFlyFlasher.exe` と `stampfly_vehicle_v2026.07.1_full.bin` を事前配置済み |
| クロスペアリング（取り違え） | コントローラが別セットの機体と繋がる | 事前ペア済みのセットを崩さない運用を徹底し、セット番号ラベルとコントローラLCDのMAC表示で照合 | 講座中は再ペアリング操作を一切行わない設計（②以降は機体ボタンでARM） |
| 低電圧で飛行時間内に電池切れ | シアン点滅＋警告音（3.4V） | 予備バッテリーに即交換 | 1セットあたり2本以上を用意（`equipment-checklist.md` §1） |
| 10台同時運用時の通信干渉 | 操縦が不安定／自動着陸が頻発 | コントローラのDevice ID割当とWiFiチャンネル分散（#01-04=1ch/#05-07=6ch/#08-10=11ch、setup-loaner-pc.md §2-2）を再確認。必要なら同時飛行数を絞る（数人ずつ順番に飛ばす運用に切替） | 干渉有無は【リハーサル実測】 |
| 教室ネットワーク制限（GitHub API等） | GUIフラッシャの「GitHub Release最新」モードが失敗・レート制限 | 当日は最初から「ローカルファイル」モードのみを使う運用に統一（Webフラッシャも同様に事前配置binへの依存はない点を確認） | `equipment-checklist.md` §1-8参照 |
| 時間超過 | 各パートが予定時間を超える | 3章の「時間超過時の短縮案」を該当パートに適用する | ③④（45分枠）が最も遅延しやすいため優先的に短縮対象とする |
| 参加者の操作不安・怪我懸念 | プロペラへの接触／機体真上を覗き込む 等 | 講師・アシスタントが常時机間巡回し、安全ルールをその都度声かけする | 保護メガネ着用の徹底、`docs/guides/safety.md` 準拠 |

## 7. アンケートと講座後作業

### アンケート

- 講座終了時（まとめパート内）にアンケートを実施する。回答は `survey/` に集約する（`survey/dxh_survey.md`（設問設計書）と `create_dxh_survey.gs`（フォーム自動生成スクリプト）を作成済み。script.google.com でスクリプトを実行しフォームURLを発行する作業が残っている）
- 本アンケートは高校教員からのフィードバック第1号にあたり、今後の高校向けカリキュラム改善の起点となる（`docs/plans/education-outreach-strategy.md` §7参照）

### 機材の復元

- 機材（機体・コントローラ）は講座終了後に工場出荷相当の状態へ復元する。復元手順は `setup-loaner-pc.md` §4「講座終了後の復元手順」を正とする（リリースFWへの書き戻し→1セットずつ再ペアリング→動作確認フライト→充電→数量確認）

### 改善メモの即日記録

- 講座終了当日中に、進行上気づいた改善点（時間配分・つまずき対応・会場レイアウト等）を本文書の該当箇所へ直接反映するか、次回セッション用のメモとして記録する
- リハーサルおよび1日目終了後の気づきは、2日目の進行までに本文書へ反映し、同一内容の講座であっても改善を1日目→2日目で回す
