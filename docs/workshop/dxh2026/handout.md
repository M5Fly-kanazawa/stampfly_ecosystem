## 1. ドローン操縦体験クイックガイド

「①ドローン操縦体験」パートで使うガイドです。機体はスタッフが事前にペアリング（機体とコントローラを1対1に紐付ける作業）済みなので、電源を入れるだけで使えます。

### 安全に飛ばすために

- 保護メガネを着用する
- 機体の真上に顔を出さない
- 飛行中の機体に手を伸ばさない
- USBケーブルを接続したまま飛ばさない（USB給電中はアーム＝モータ動作許可が拒否されます）

### 起動とLEDの見方

機体を平らな床に置いて電源を入れると、内蔵LEDの色と点滅パターンで状態が分かります。今日の演習で見る色はこれだけです。

| LED表示 | 意味 | すること |
|---------|------|---------|
| 白（常灯） | 起動・初期化中 | 待つ |
| マゼンタ（点滅） | ジャイロ校正中 | **機体に触らない**（動かすと校正がやり直しになります） |
| 緑（常灯）＋ピッ×3 | 校正完了・準備完了 | 操作開始OK |
| シアン（点滅） | バッテリー低電圧（約3.4V） | 着陸させて電池交換 |
| 青（高速点滅） | ペアリング待機中 | 今日は基本的に見ません（見えたらスタッフへ） |

機体LEDの色は、選んでいる飛行モードによっても変わります（今日はPOS_HOLDのマゼンタを使います）。

| モード | LED色 |
|--------|-------|
| STABILIZE（姿勢安定） | 黄緑 |
| ACRO（機体レート制御） | 青 |
| ALT_HOLD（高度保持） | オレンジ |
| POS_HOLD（位置保持） | マゼンタ |

### 操縦手順

1. **POS_HOLDに切り替える**: コントローラの左ボタンを2回押す（OFF→ALT_HOLD→POS_HOLD）。機体LEDが**マゼンタ**になったことを確認する
2. **ARM（アーム、モータ動作許可）**: コントローラのスロットル側スティック（Mode 2では左スティック）を押し込む → 自動的に離陸し、高度0.5mでホバリング（スロットル操作は不要）
3. **移動する**: スティックは全軸バネ復帰式（倒すと動き、離すと中央に戻るタイプ）。少し倒すとその方向へ移動し、手を離すとその場で静止します（位置保持精度は実測±6〜7cm）
4. **DISARM（ディスアーム、モータ動作停止）**: もう一度スティックを押し込む → 自動着陸
5. **緊急停止**: 着陸中にもう一度DISARMを押す → その場で即座にモータ停止

### してはいけないこと

| 禁止事項 | 理由 |
|---------|------|
| 機体の真上に顔を出す | プロペラガード越しでも危険 |
| 飛行中の機体に手を伸ばす | 接触事故防止 |
| USBケーブルを繋いだまま飛ばそうとする | USB給電中はARMが拒否される（そもそも飛べません） |

### 覚えておくこと

- 通信が0.5秒途絶えると自動的に着陸します（フェイルセーフ機能）
- 床には模様が必要です（機体下向きのカメラが床の模様を見て位置を検出する仕組みのため、会場には模様入りマットを敷いてあります）
- バッテリーは満充電で約4分飛べます（300mAh・1セルLiPo）

## 2. ファームウェア書き込み（Webフラッシャ）

「②開発環境＋ビルド不要書き込み」の実習パートです。ここでいう「ファームウェア」とは、機体の中で動いているプログラム本体のことです。今日は「Webフラッシャ」というブラウザだけで使える書き込みツールを使い、最新版のファームウェアを機体に書き込みます（「書き込み＝フラッシュ」と呼びます）。

### 事前確認

| 項目 | 内容 |
|------|------|
| ブラウザ | Microsoft Edge（Google Chromeでも可）。**Safari・Firefoxは非対応**です（「Web Serial」というブラウザ機能を使うため） |
| ケーブル | USB-Cの「データ通信対応」ケーブル（充電専用ケーブルでは書き込めません） |
| ドライバ | **不要**です。StampFlyのESP32-S3チップは内蔵USB機能を使うため、Windowsは「USB JTAG/serial debug unit (COMx)」という名前で自動認識します |

### 書き込み手順

Webフラッシャのページ（`https://m5fly-kanazawa.github.io/stampfly_ecosystem/flash/`）は貸出PCで開いた状態から始めます。

1. **機体の電源を入れ、USB-Cケーブルでパソコンに接続する**

2. **ページの「StampFly 本体」カードにある「⚡ インストール」ボタンをクリックする**

   【スクリーンショット: 「StampFly 本体」カードと「⚡ インストール」ボタンが表示されたWebフラッシャのトップ画面】

3. **ブラウザ上部にポート選択ダイアログが表示されるので、一覧から機体のポート（「USB JTAG/serial debug unit」のような名前）を選び「接続」をクリックする**

   【スクリーンショット: ブラウザのポート選択ダイアログ。ポート一覧と「接続」ボタンが見える状態】

4. **インストール画面が開いたら、「Erase device（全消去）」のチェックボックスは外れたまま（本講座ではOFFのまま）にして、インストールを実行する**

   【スクリーンショット: インストール画面。「Erase device」チェックボックスがOFFになっている状態とINSTALLボタン】

5. **進捗（%）が表示され、書き込みが進む。完了すると機体が自動的に再起動する**

   【スクリーンショット: 書き込み中の進捗バー（%表示）】

   【スクリーンショット: 書き込み完了後の画面（完了メッセージ・再起動の案内）】

6. **機体の起動音（ドミソ→…→ピッピッピッ）が鳴り終わり、LEDが緑の常灯になるまで、機体を水平な場所に置いたまま動かさない**（ジャイロ校正中のため。「1. LEDの見方」の表を参照）

### 書き込み後について（重要）

Webフラッシャが書き込む「full」イメージ（起動プログラム＋パーティション情報＋アプリ本体をまとめたもの）は、機体の設定保存領域（**NVS**＝Non-Volatile Storage・不揮発性メモリ。電源を切っても消えない記憶領域）も上書きします。そのため、**「Erase device」のチェックの有無にかかわらず、書き込むとペアリング情報とパラメータ設定が工場出荷状態に戻ります**（未ペア状態＝次回電源を入れると青の高速点滅＝ペアリング待機になります）。

今日のカリキュラムでは②の後にこの機体を飛ばす予定はないため、**そのままでOKです**。ペアリングの復元は後ほど講師が行います。

### うまくいかない時の早見表

| 症状 | 対処 |
|------|------|
| ポートが一覧に出てこない | 別のUSBケーブルを試す（データ通信対応か確認）／ポートを使用中の他アプリ（シリアルモニタ等）を閉じる／別のUSBポートを試す |
| 書き込みが何度も失敗する | 一度ケーブルを抜き、機体のBOOTボタンを押しながらUSBを挿し直す（ROMブートローダーという書き込み専用モードに入ります）。その状態のまま再度インストールを試す |
| ポートが使用中と表示される | `sf monitor` やシリアルモニタなど、ポートを使っている他のアプリを閉じる |

## 3. 開発環境とは

「StampFly Ecosystem」は、機体・コントローラのファームウェア、開発ツール、ドキュメントをすべてまとめて公開している教育・研究用のプラットフォームです。GitHub（ソースコードを保存・公開するWebサービス）上で無償公開されています。

| 用語 | 説明 |
|------|------|
| リポジトリ | プログラムのソースコードやドキュメント一式が入っている保管場所のこと |
| ビルド | 人が書いたソースコード（人が読み書きできる文章形式のプログラム）を、機体のマイコンが実行できる形式に変換する作業 |
| フラッシュ（書き込み） | ビルドしてできたプログラムを機体のマイコンに転送し、記憶させる作業 |

自分のパソコンでゼロから開発環境（ビルドに必要なソフトウェア一式）を整える場合は、リポジトリに入っている `install.bat` を1回実行するだけで、必要なツール（ESP-IDFというマイコン開発環境と `sf` コマンド）が自動的にインストールされます。詳しい手順は `docs/setup/windows.md` にまとまっています。

**今日の貸出PCはこの環境構築が事前に完了した状態でお渡ししています。** 「開発環境のインストール」パートでは、この `install.bat` を使った構築の流れをデモでご覧いただく形になります（実際に自分の手でインストールする作業は行いません）。

## 4. プログラム書き換え・モータの制御

「③④プログラム書き換え・モータの制御」の実習です。実際にプログラムの数値を書き換えて機体に書き込み、モータの回転で結果を確認します。

### 安全ルール

| ルール | 理由 |
|--------|------|
| 保護メガネを着用する | 万一の飛散に備える |
| 機体上部のM5StampS3（基板モジュール）を上から指で押さえた状態で確認する | 複数モータが同時に回ると機体が飛び上がるため、突然の離陸を物理的に止められる状態にしておく |
| Duty（モータの出力の強さ。0.0〜1.0で指定し、大きいほど回転が強い）は**上限0.15**を守る | ファームウェア側では上限が強制されていません。小数点を打ち間違えて「1.0」と書いてしまうとモータが全開で回ります |
| 数値を書き換えたら、ビルドする前に隣の人と画面を見せ合ってダブルチェックする | タイポ（打ち間違い）の早期発見 |
| プロペラは付けたまま作業する | 外す必要はありません。1.のルールで安全を確保します |

### 手順

配布PCではリポジトリと開発環境のセットアップが完了済みです。コマンドプロンプト（文字でコマンドを打ち込んでパソコンを操作する黒い画面）を使って進めます。

1. コマンドプロンプトでリポジトリのフォルダに移動する（【リハーサル確認: 配布PC上の実際のフォルダパス・起動方法】）
2. 開発環境をアクティブ化する（毎回ターミナルを開くたびに必要）
   ```cmd
   setup_env.bat
   ```
3. 実習コードを開く（VSCodeというエディタが自動的に起動します）
   ```cmd
   sf lesson edit
   ```
4. 下記「実習コード」を参考に、回したいモータの行の数値（Duty）を書き換えて保存する
5. ビルドする（書いたコードを機体が実行できる形式に変換する）
   ```cmd
   sf lesson build
   ```
6. 機体をUSB接続した状態で書き込む（書き込み後、シリアルモニタ＝機体からのログ表示画面が自動的に開きます。終了は `Ctrl+]`）
   ```cmd
   sf lesson flash
   ```
7. シリアルモニタを終了したら、**USBケーブルを外し**、バッテリーを接続して機体の電源を入れる
8. 起動LEDシーケンス（下表）を目で追い、緑点灯＋ビープ3回になるまで待つ
9. **機体本体ボタンを1回クリック＝ARM**（設定したDutyでモータが回転開始）。**もう1回クリック＝DISARM**（モータ停止）

コントローラは今回の実習では使いません（機体本体ボタンだけで動作確認します）。

### 実習コード

以下をそのまま `user_code.cpp` に貼り付けてください（モータIDと数値以外は変更不要です）。

```cpp
#include "workshop_api.hpp"

// =========================================================================
// Motor duty test (hardcoded)
// 各モータの Duty をハードコードする
// =========================================================================
//
// Motor IDs / モータ ID:
//   1 = FR (右前)   2 = RR (右後)
//   3 = RL (左後)   4 = FL (左前)
//
// Duty range: 0.0 - 1.0
//   0.0  = stop / 止める
//   0.10 = spin at 10% / 10% で回す
//   このチュートリアルでは 0.15 を上限とする

void setup()
{
    ws::print("Motor duty test");

    // Do NOT auto-arm in code. Arming is controlled by the controller's
    // ARM button so motors never spin until you intentionally press it.
    // コードでは自動 ARM しない。アーム/解除はコントローラの ARM ボタンで
    // 行うので、意図的に押すまでモータは絶対に回らない
}

void loop_400Hz(float dt)
{
    // ----- Set each motor's duty here / 各モータの Duty をここで設定 -----
    ws::motor_set_duty(1, 0.10f);   // FR (右前)
    ws::motor_set_duty(2, 0.00f);   // RR (右後)
    ws::motor_set_duty(3, 0.00f);   // RL (左後)
    ws::motor_set_duty(4, 0.00f);   // FL (左前)
    // -------------------------------------------------------------------
}
```

回したいモータの行の数値（例: `0.00f`）を `0.10f` などに書き換えるだけです。複数モータを同時に回すこともできます。**Duty上限0.15を超えないこと。**

### 起動LEDシーケンス（実習ファーム）

USBを外してバッテリー駆動に切り替えた後、機体の電源を入れると以下の順でLEDが変化します。

| 段階 | LED表示 | 状態 |
|------|---------|------|
| 1 | 白でゆっくり明滅 | 「機体を地面に置いて待つ」カウントダウン（約3秒） |
| 2 | 青でゆっくり明滅 | センサ初期化中 |
| 3 | マゼンタで点滅 | センサ安定化待ち（約3秒・触らない） |
| 4 | **緑点灯＋ビープ3回** | **起動完了・操作可能（ここでARMできます）** |

### 改造課題

時間に余裕があれば、以下を自分で試してみてください。書き換え→ビルド→書き込みの流れ（上記の手順4〜6）を繰り返します。

| # | 課題 |
|---|------|
| 1 | 別のモータを回してみる（モータIDを1〜4の間で変える） |
| 2 | 複数のモータを同時に回してみる（2行以上を0以外の数値にする） |
| 3 | Dutyを0.05・0.10・0.15と変えて、音や振動の違いを聞き比べる |

**発展課題**: 4つのモータを2秒ごとに自動で切り替えて回すこともできます。以下は `firmware/workshop/lessons/lesson_01_motor/solution.cpp` の巡回パターンを、本講座の安全設計（機体ボタンでのみARMする＝コード内で自動ARMしない）に合わせて書き換えたものです。

```cpp
#include "workshop_api.hpp"

// =========================================================================
// Advanced: cycle through motors every 2 seconds
// 発展課題: モータを2秒ごとに巡回させる
// =========================================================================

static uint32_t motor_timer = 0;
static int current_motor = 1;

void setup()
{
    ws::print("Lesson 1: Motor cycle (advanced)");

    // Do NOT auto-arm in code (workshop safety design).
    // 安全のためコードでは自動 ARM しない（機体ボタンでのみ ARM する）
}

void loop_400Hz(float dt)
{
    // 400Hz * 2s = 800 ticks per motor
    // 400Hz × 2秒 = 800ティック/モータ
    motor_timer++;
    int phase = (motor_timer / 800) % 4;
    current_motor = phase + 1;

    // Set only the current motor, stop the others
    // 現在のモータのみ回転、他は停止
    for (int m = 1; m <= 4; m++) {
        if (m == current_motor) {
            ws::motor_set_duty(m, 0.10f);
        } else {
            ws::motor_set_duty(m, 0.0f);
        }
    }
}
```

## 5. トラブルシューティング早見表

| 症状 | 原因 | 対処 |
|------|------|------|
| ビルドエラーが出る（赤字で `error:` と表示される） | コードの打ち間違い（カンマ・セミコロン抜け、括弧の対応ミス等） | エラーメッセージの一番上の行に出るファイル名と行番号（例: `user_code.cpp:15`）を確認し、その行を実習コードと見比べる |
| 書き込みが失敗する（`sf lesson flash` が失敗） | USBケーブル・ポートの問題 | ケーブルを交換する／シリアルモニタ等ポートを使う他アプリを閉じる／機体のBOOTボタンを押しながらUSBを挿し直す |
| モータが回らない | ARMし忘れ／バッテリー未接続／USB接続したまま | 機体本体ボタンを1回クリックしたか確認する／USBを外してバッテリー駆動になっているか確認する（USB給電中はARMが拒否されます） |
| 起動LEDが緑にならず、マゼンタのまま | 校正中に機体を動かしてしまった | 機体を静かに置き直し、緑点灯＋ビープ3回になるまで待つ |
