# MOTOR_CT 切替（バックログ#3 ファーム側）ログ駆動整合分析

生成日: 2026-07-27 / リポジトリ変更なし（分析のみ）

## 結論（判定）

**仮説「新チェーンは補正なし(corr≈1.0)でホバー実測dutyを予測する」は不支持（反証された）。**

新チェーンの implied_corr（実測 duty+電圧を新モータ曲線で逆算した推力 ÷ 必要ホバー推力 mg）は
1.0 に近づくどころか、旧チェーンが 1.0 からずれる量（+0.083）とほぼ同じ大きさだけ、
反対側に（−0.091）ずれている。9 個の独立した日付いずれでも同じ傾向（1標本 t検定
p=0.0013、n=9）。**「切替＝corr撤廃」という前提は成立しない。**

ただし、新旧チェーンの implied_corr の比は 9 日間を通じて 0.8388 ± 0.00005
（相対ばらつき 0.006%）と極めて安定しており、切替は「形が変わる」のではなく
「ほぼ一定倍率でスケールし直す」だけであることも分かった。したがって、
`hover.thrust_corr` の既定値を 1.12 → 約 0.90 に合わせて変更するなら、
切替自体は数値的には成立する（既存のオンボード・ホバー推力学習が前提のまま）。

## データと抽出基準

- 対象: `logs/stampfly_udp_*.jsonl`（2026-06・2026-07 のみ）
- 選定基準（結果を見る前に固定）: ALT_HOLD(mode=2)/POS_HOLD(mode=3) の
  サンプルが合計 15 秒以上あるログ → candidate 42 本
- ホバー区間の機械的抽出（1.5秒窓の移動統計、恣意的な区間選びを排除）:
  - flight_mode ∈ {ALT_HOLD, POS_HOLD}
  - 高度(ESKF, posvel.pos[2]の符号反転)の移動標準偏差 < 0.02 m
  - 鉛直速度(posvel.vel[2]の符号反転)の絶対値最大 < 0.10 m/s
  - ロール/ピッチ/ヨースティック絶対値最大 < 0.05（中立）
  - duty 0.05〜0.95（armed・非飽和）
  - 連続 1.0 秒以上を1区間として採用
- 結果: **24 本のログ・9 個の異なる日付・85 区間・合計 345.2 秒のホバー**を抽出

## 一次データでの検証（反証原則）

- `motor_duty[4]` は `data_stream_wire.hpp` の `WireCtrlRef` 定義どおり
  FR/RR/RL/FL の実 duty [0,1]（actuator.cpp のミキサー後・クランプ後の値そのもの）と
  ソースコードで確認済み。
- `status.voltage` は `sensor_power`（INA3221）の実測バッテリ電圧で、
  actuator.cpp の `batteryVoltage()` が使う値と同一。
- 旧チェーンで **duty を順方向再構成**（ログの `total_thrust`/4 →
  duty 予測）し、ログの実 duty と突き合わせたところ、残差は 0.003〜0.004
  （float32 丸め＋モータ間トルク非対称程度）— Python 再実装が正しいことを確認。
- 旧チェーンで **duty を逆算**して得た「推力/mg」比は、ログが直接持つ
  `total_thrust`/mg 比と 0.001 未満で一致 — 逆算ロジックも数値的に正しい。
- `current_ma`（2026-07 の7ログのみ収録）を使った副次検証は**未確認/結論不能**として
  報告: 新チェーンの Rm/Km から予測した合計バッテリ電流(4×(V−Km·ω)/Rm + 0.1A)は
  約3.5〜3.7A だが、ログの `current_ma` は 325〜330mA でほぼ一定（duty 0.60〜0.67・
  7セッションに渡り標準偏差 1.6mA）— モータ負荷に対して電流が全く変化しておらず、
  この電流チャンネルはアビオニクス/ロジック系統のみを測っていて、バッテリ全電流
  （モータ込み）ではない可能性が高い。ハードウェアの INA3221 チャンネル配線確認が
  必要（本分析のスコープ外、Rm/Km の裏付けとしては使えない）。

- プールした 85 区間の平均: 旧 1.084±0.063（範囲 0.991-1.265）、
  新 0.909±0.052（範囲 0.831-1.061）
- 1標本 t検定（H0: 平均=1.0、n=9日付）: 旧 t=3.70, p=0.0061／新 t=−4.84, p=0.0013
  — どちらも 1.0 からの有意なずれ。新チェーンの方が有意性はむしろ強い。
- 新/旧 implied_corr の比は 9 日間で **0.83881 ± 0.00005**（相対ばらつき 0.006%）
  — duty 0.585〜0.77・電圧 3.4〜4.1V の実運用範囲で、切替はほぼ純粋な定数倍
  スケーリングとして働く（形は変わらない）。
- 両チェーンとも implied_corr は duty 平均と正相関（r=0.78、旧新で同一）。
  これは duty=V/Vbat がバッテリ内部抵抗・配線・ESC の電圧降下を無視している
  ことに起因すると考えられる、新旧共通の残存誤差（CT切替では解消しない）。

## 推奨

- **「切替＝補正撤廃」という当初想定でのバックログ#3実施は保留**（仮説不支持）。
- 切替を実施するなら（例: KAPPA が既に実測 Cq/Ct 由来であることとの一貫性確保が
  目的であれば）、`hover.thrust_corr` 既定値の同時変更（1.12→約0.90）を**必須条件**
  とする。2026-07-15 の KAPPA 修正時に `rate.yaw.kp`/`max_torque` を同時再スケール
  した前例と同じ運用。
- オンボード・ホバー推力学習（`hover.thrust.learn`, 既定 on）は新旧どちらの
  チェーンでも残差（±5〜6%のセッション間ばらつき）を吸収する主力機構であり続ける
  ため、切替自体の可否を左右する安全上のブロッカーではない。
- 切替を採用する場合、SIL ゲート通過に加え、実機での ALT_HOLD 検証飛行を
  最低1回行うことを推奨（`docs/architecture/simulation-policy.md` の
  Model Identity 方針に整合）。
